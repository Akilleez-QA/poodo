# Getting help

Start with [README.md](README.md), [getting started](docs/getting-started.md),
[how POODO works](docs/how-it-works.md), and the [examples](examples/README.md).
For validator behavior and the limits of structural checks, read the
[evaluation guide](docs/evaluation.md).

Ask how-to questions, report reproducible defects, or propose improvements through
[Issues](https://github.com/Akilleez-QA/poodo/issues). Include the commit or version,
agent host or Python environment as relevant, reproduction steps, expected behavior,
and actual behavior. Separate observed failures from suspected causes and use
synthetic examples. Remove secrets, personal data, private paths, and private traces.

For contributions, follow [CONTRIBUTING.md](CONTRIBUTING.md). Explain the concrete
problem and evidence for the proposed behavior; mark unmeasured behavioral effects
explicitly. Follow [SECURITY.md](SECURITY.md) for sensitive reports and the
[Code of Conduct](CODE_OF_CONDUCT.md) for conduct concerns. Private contact:
[craig@nh3.biz](mailto:craig@nh3.biz). No support response time is guaranteed.
