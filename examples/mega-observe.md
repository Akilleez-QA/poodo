# Prepare a Mega Observe run

Synthetic invocation example. No searches, paid calls, or 40,000-record run have been performed for this example.

## Prompt

```text
Use $poodo in Mega Observe mode to map the failure mechanisms, constraints,
and intervention options around municipal water loss. I want 200 meaningful
categories, evaluated 200 distinct ways each. Prepare a costed charter first;
do not start paid work yet. Include source coverage, skeptical review,
resumption, and the conditions under which you would call the run incomplete.
```

## Expected next step

Clarify the decision and boundaries: geography, infrastructure types, time span, accessible languages, operational data access, and intended use. Propose source families and a pilot that can estimate the full cost, including review and retries. Establish authority and a ceiling before dispatching expensive work.

The taxonomy must emerge from research. Do not prepopulate 200 headings before investigating or treat 200 variants of “pipe leakage” as separate categories. A useful evaluation asks a concrete question with a discriminator; a generic paragraph about importance is not an evaluation.

## Example of one possible question

For a category concerning measurement error, ask whether the stated loss estimate separates meter error from actual physical leakage. Identify the measurement protocol, evidence, uncertainty, and which observation would change the estimate. Whether this deserves a category or subcategory depends on the researched taxonomy.

This is one illustrative question, not a source-backed finding or a counted cell. The full run must preserve source identity and review for every accepted record.

## Completion boundary

A meaningful result could reveal that fewer than 200 categories are defensible, or that many completed evaluations remain uncertain. Report that directly. Spending the budget is not an acceptance criterion, and reaching 40,000 rows is not proof of a complete map.
